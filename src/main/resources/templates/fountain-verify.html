Project Overview

Fountain Verify is a digital certificate verification platform developed as part of Fountain Information Service (FIS). It helps certificate issuers manage certificate records and makes verification more convenient for employers, institutions, and other people who need to confirm certificate details.

Each certificate can have a unique certificate number and a corresponding QR code. Scanning the QR code can open the public verification page, where the certificate's recorded status and details can be checked.

Key Features

Certificate Management

Authorized administrators can create, view, update, and manage certificate records.

QR Code Generation

Generates QR codes that direct users to a certificate's public verification page.

Public Verification

Allows visitors to check a certificate using its unique certificate number or verification QR code.

Authentication and Access Control

Provides user login and role-based protection for administrative certificate-management features.

Certificate Status

Verification checks certificate status and expiry dates before displaying the result.

Responsive Web Interface

Uses server-rendered web pages designed to present certificate information across screen sizes.

Application Routes & API Documentation

Fountain Verify uses Spring MVC controllers to handle certificate verification, user certificate pages, and administrator certificate-management forms.

Base URL for local development http://localhost:8080

The routes below are based on the application's verified controller mappings. These are primarily HTML-page and form endpoints; they are not represented as JSON REST responses.

1. Public Verification

GET /verify

Opens the verification form or checks a certificate when a certificate number is supplied. The result page can display VALID, INVALID, BLOCKED, REVOKED, or EXPIRED.

Public access

Query parameter: certificateNumber

GET /verify?certificateNumber=FV-2026-0001

2. Authenticated User Routes

GET /my-certificates

Opens the authenticated user's certificate page. Access is restricted to signed-in users.

Authentication required
GET /my-qr-codes

Displays QR codes for certificates assigned to the currently authenticated user.

Authentication required

3. Administrator Certificate Management

The following routes are defined in the certificate controller protected by the ADMIN role.

GET /certificates/list

Displays the certificate-management list.

ADMIN only
GET /certificates/create

Opens the form for creating a certificate.

ADMIN only
POST /certificates/create

Submits certificate details, including the certificate number, recipient, course, issuer, dates, and assigned user.

ADMIN only
GET /certificates/view/{id}

Displays a certificate by its database ID.

ADMIN only
GET /certificates/edit/{id}

Opens the edit form for an existing certificate.

ADMIN only
POST /certificates/edit/{id}

Submits changes to certificate details, status, dates, and the assigned user.

ADMIN only
POST /certificates/regenerate-qr/{id}

Regenerates the QR code for an existing certificate.

ADMIN only
POST /certificates/delete/{id}

Submits a request to delete an existing certificate.

ADMIN only

4. QR Code Image Generation

GET /qrcode?text=...

Generates a QR code from the supplied text and returns it as a PNG image. The controller uses ZXing and generates a 300 × 300 image.

Access depends on Spring Security configuration

Query parameter: text

GET /qrcode?text=Hello

Response content type: image/png

Implementation note: These mappings document the verified Spring MVC controller routes. Most application routes render HTML pages or process form submissions, while /qrcode returns a PNG image. A separate JSON REST API would need its own API controller and JSON request/response contracts.
