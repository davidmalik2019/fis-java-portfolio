JAVA PROJECT #1

JobConnect

A Java backend project designed to connect job seekers and employers, with user authentication, role-based access, and REST API functionality.

← Back to Featured Projects

Project Overview

JobConnect is a job platform project built to demonstrate practical Java backend development. It provides a foundation for connecting people looking for employment with employers seeking candidates.

The project helped me practise building REST endpoints, managing users and roles, connecting an application to a database, and implementing authentication for protected resources.

Key Features

User Authentication

Supports user authentication and token-based access for protected API resources.

Role-Based Access

Separates job seeker, employer, and administrator roles to support role-specific functionality.

REST API

Provides backend API endpoints for job listings, applications, user accounts, and administration.

Database Integration

Uses MySQL to support persistent application data.

Technologies Used

The project uses the following technologies and development tools:

Java Spring Boot REST API MySQL Spring Security JWT

REST API Documentation

JobConnect exposes REST endpoints for authentication, user management, job listings, applications, and administration. The reference below documents the application's configured routes and access requirements.

Local development: The base URL is commonly http://localhost:8080 when JobConnect is running on port 8080. Use the actual port configured for your JobConnect instance. This documentation does not mean the API is publicly deployed.
Authentication: For protected endpoints, send the JWT returned by login in the HTTP request header:
Authorization: Bearer YOUR_JWT_TOKEN
Never publish a real JWT, password, or private account information.

1. Authentication

Method Endpoint Access Description
POST /auth/login Public Authenticates a user and returns a JWT with username and role information.

Login request

{
  "username": "jobseeker1",
  "password": "your-password"
}

Successful login response

{
  "message": "Login successful",
  "username": "jobseeker1",
  "token": "your-jwt-token",
  "role": "JOB_SEEKER"
}

The JSON field names above are confirmed by the LoginRequest and LoginResponse DTOs. The values are illustrative.

2. User Accounts and Profiles

Method Endpoint Access Description
POST /users/register Public Registers a job seeker.
POST /users/register-employer Public Registers an employer.
GET /users/me Authenticated Returns the signed-in user's profile.
PUT /users/me Authenticated Updates the signed-in user's profile fields.
POST /users/change-password Authenticated Changes the signed-in user's password after validation.
GET /users Admin Lists users.
GET /users/{id} Admin Retrieves a user by ID.
POST /users Admin Creates a user account.
PUT /users/{id} Admin Updates an account.
DELETE /users/{id} Admin Deletes a user account.

User response example

{
  "id": 1,
  "fullName": "Jane Doe",
  "username": "janedoe",
  "email": "jane@example.com",
  "phone": "08012345678",
  "role": "JOB_SEEKER"
}

This example reflects the fields in the UserResponse DTO. It does not expose a password.

3. Job Listings

Method Endpoint Access Description
GET /jobs Public Lists available job records.
GET /jobs/{id} Public Retrieves a job by ID.
GET /jobs/my Employer Lists jobs posted by the signed-in employer.
POST /jobs Employer Creates a job listing for the signed-in employer.
PUT /jobs/{id} Employer and owner Updates a job belonging to the signed-in employer.
DELETE /jobs/{id} Employer and owner Deletes a job belonging to the signed-in employer.

4. Job Applications

Method Endpoint Access Description
POST /applications Job seeker Submits an application for a job.
GET /applications/my Job seeker Lists applications submitted by the signed-in job seeker.
GET /applications Employer or admin Returns applications associated with jobs matching the signed-in username in the controller.
GET /applications/{id} Authenticated owner Retrieves an application after an ownership check.
PUT /applications/{id} Authenticated owner Updates an application while its status is Pending.
DELETE /applications/{id}/withdraw Authenticated owner Withdraws a Pending application.
PUT /applications/{id}/accept Employer or admin Accepts a Pending application, subject to the job ownership check.
PUT /applications/{id}/reject Employer or admin Rejects a Pending application, subject to the job ownership check.

5. Administration

Method Endpoint Access Description
GET /admin/statistics Admin Returns platform statistics.
GET /admin/users Admin Lists user information.
PUT /admin/users/{id}/role Admin Updates an eligible user's role.
GET /admin/jobs Admin Lists all jobs.
GET /admin/jobs/{id} Admin Retrieves a job by ID.
DELETE /admin/jobs/{id} Admin Deletes a job.
GET /admin/applications Admin Lists all applications.
GET /admin/applications/{id} Admin Retrieves an application by ID.
DELETE /admin/applications/{id} Admin Deletes an application.
Implementation note: Endpoints that change or delete records may perform additional ownership, role, or application-status checks inside their controllers. A route being listed here does not bypass those checks.
